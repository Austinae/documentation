SuprSend let's you design & personalize responsive templates for your email notifications with a variety of options and functionalities. You can event re-use a single template for different users, tenants, and events - instead of manually creating separate ones for each use case.

## Designing Email Templates

<Steps>
  <Step title="Navigating to the template page" stepNumber="1">
  On the left side-bar on SuprSend's [Dashboard](https://app.suprsend.com/en/staging), select `Templates`. Now, click on `New Template` and give it a name.
  </Step>
  <Step title="Enabling the email channel" stepNumber="2">
  A new template page will open. Here, select the notification channel as `Email`, and click on `Enable Channel`.
  </Step>
<Step title="Choosing the editor" stepNumber="3">
 You will land onto a blank page of the drag-and-drop editor. Find items and contents to add onto your template from the right-section of the editor. [Know about each section in detail.](/docs/email-template#)

 ![](/images/docs/email-template-editor-menu.png)

  SuprSend supports two ways to design emails:
  - **HTML editor** - Direct code-based editor for custom HTML emails. (best for migrating existing templates from cross-platform tools)
  - **Drag-and-drop editor** - (recommended) visual editor to build layouts visually without code.

</Step>
</Steps>

### Using HTML Editor

If you're migrating from another platform or already have HTML templates, the HTML editor is the best option to directly import your existing code into SuprSend.

You can `switch to HTML editor` using the toggle button at the bottom of the editor.

<Warning>
  The template preview in SuprSend may not exactly match how it renders in email clients like Gmail or Outlook.

  Many email clients strip out `<script>` tags and some `<style>` blocks, which can break formatting or layout.

  For compatibility, refer to [Campaign Monitor's CSS Support Guide](https://www.campaignmonitor.com/css/) to verify which styles are supported across major email clients.
</Warning>


### Using Drag & Drop Editor

This is the default editor you will land after creating a new template. It allows you to visually build responsive email templates without writing code.

Email Template is composed of three following categories in the drag-and-drop editor:
  - **Body**- The outermost background and global settings (e.g., width, font, alignment).
  - **Blocks**- Rows that define the layout structure (e.g., one-column, two-column).
  - **Content**- Elements placed inside blocks, like: headings, text, buttons, images, tables, etc.
  - **Images**- Search and add images to your template.
  - **Upload**- To insert images by uploding.

You can drag and place the components as required. The email designed would be responsive. This could be previewed by clicking on preview bar in bottom left corner, for each desktopm and mobile view.
Learn more about [Email Preview](/docs/email-template#email-preview).

After preparing your template, the next step is to add other details like subject, from name, from email, reply to and email markup.
  ![](/images/docs/drag-and-drop.gif)

### Responsive Design Tips

Emails designed in the drag-and-drop editor are responsive by default. This means the layout will automatically adjust for mobile and desktop views when sent to users.

You can preview how your template will look across devices by using the `Preview` bar in the bottom left corner.

![2482](/images/docs/ab6f529-Screenshot_2021-10-19_at_4.12.49_PM.png "Screenshot 2021-10-19 at 4.12.49 PM.png")

SuprSend handles common responsive behaviors such as:

- **Column stacking**- Multi-column rows stack vertically on mobile
- **Font size and padding**- Automatically adjusted for smaller screens

<Tip>
  You can show or hide specific elements on desktop and mobile individually. Padding and alignment can also be customized separately per device.
</Tip>

## Adding Dynamic Content in Email

Dynamic content (e.g. name, location, order details) is added in an email for personalizing it to each user. We add **Variables** in tempaltes to achieve this. While rendering email, these variables convert to actual values personlaized to their user.

**Adding Variables:**
SuprSend uses [Handlebars language](https://handlebarsjs.com/guide/) to add variables in their templates. They can be used in both the editors- HTML and drag-and-drop. Variables can be used inside any content block (text, buttons, subject lines, etc.) throughout the email.

We use double `{{` curly braces to include variables in the template. However, in case the variable includes any special characters, we instead use triple `{{{` curly braces for the same.

Some use-cases of Variables:
  - `{{user.name}}` - At parent-level, where variable name is `user`.
  - `{{event.location.city}}` - For nested variables, where the parent variable is `event`, and property `location` and `city` is nested.
  - `{{{name>1}}}` - Where a special character is included in the variable.
  - `{{event.[first name]}}` - In case the variable contains array to be included. To add array names, you need to use an functionality called [Merge Tags](/docs/email-template#adding-merge-tags).


<Note>
  In handlebars language, the special character carry a meaning. This is why on printing variables lke `{{{name>1}}`, it might not acquire the expected value later when rendered. Therefore, to avoid this use triple `{{{` curly braces for variables with special characters.
</Note>

For using variables in the template, you need to add sample values for them in the `Mock Data` button present at the top-right section. [Learn how to add mock data](/docs/templates#adding-dynamic-content)

After adding Mock data, you can see the variables in the auto-suggestions, as you write the template.
Auto-suggestions could be seen while initiating `{` somewhere, or while using Merge Tags.

### Adding Merge Tags

  Merge tags allow end-users to dynamically insert variable content into their email. These variables are replaced with actual values during email send, based on the trigger data.
  Merge tags can be inserted into a block of text by clicking on the “Merge Tags” button in the text editor toolbar. The button will only appear if variables are already defined in the global Mock Data panel.

  <Warning>
    The Merge Tag button only appears when variables are alreadydefined in the global Mock Data panel.
  </Warning>

### Adding Array Elements

Arrays in email templates allow you to dynamically display lists of items (like products, orders, or notifications). Unlike simple variables, array elements require a special approach using **Merge Tags** since they don't appear in the standard dropdown suggestions when typing `{`.

  Arrays are perfect for scenarios like:
  - Product catalogs with multiple items
  - Order summaries with line items
  - Notification lists
  - Dynamic content blocks

Follow these steps to add array elements to your email template:

<Steps>
  <Step title="Define your array structure in Mock Data">
    First, declare your array object in the **Mock Data** panel. For example, if you want to display a list of products, define an array like this:

    ```json
    {
      "products": [
        {
          "name": "Premium Headphones",
          "image": "https://example.com/headphones.jpg",
          "price": "$299"
        },
        {
          "name": "Wireless Mouse",
          "image": "https://example.com/mouse.jpg",
          "price": "$49"
        }
      ]
    }
    ```

    ![](/images/docs/137de20-c5f7859-Screenshot_2021-11-20_at_6.08.07_PM.png "Sample array structure in Mock Data")
  </Step>

  <Step title="Select a Row for dynamic content">
    In your email template, select a **Row** component where you want to display the array elements. You'll notice an additional button appears in the bottom left corner of the row.

    ![](/images/docs/1bfe489-Screenshot_2021-11-22_at_2.33.08_PM.png "Row selection with dynamic content button")
  </Step>

  <Step title="Associate the array with the row">
    Click the dynamic content button to see all arrays defined in your Mock Data. Select the array you want to use in this row.

    ![](/images/docs/05cb7c2-Screenshot_2021-11-22_at_2.36.16_PM.png "Array selection dropdown")

    <Frame caption="The selected row will turn green to indicate it's now associated with array elements">
      <img src="/images/docs/a4b4ac9-Screenshot_2021-11-22_at_2.41.20_PM.png" />
    </Frame>
  </Step>

  <Step title="Add array variables to your content">
    Once associated, array element variables will appear in auto-suggestions when you type `{` or click 'Merge Tags'. Select the variables you want to display, and the row will automatically repeat for each array element when the email is sent.

    ![](/images/docs/f9ef60f-Screenshot_2021-11-22_at_2.44.44_PM.png "Array variables in auto-suggestions")
  </Step>
</Steps>

<Tip>
  **Pro tip**: You can use array variables like `{{products.0.name}}` to access specific array elements, or use the row association method above for dynamic repetition.
</Tip>

## Email fields description

| Field        | Description                                                                                                                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Subject      | Small text box. Use **`handlebarsjs`** to add variables                                                                                                                                               |
| From Name    | Display name which tells recipient who sent the email                                                                                                                                                 |
| From Email   | Domain name must be registered with the vendor                                                                                                                                                        |
| Reply To     | Domain name must be registered with the vendor                                                                                                                                                        |
| cc           | *Optional* List of email ids. It is not a part of email design. To be sent with Events data or from Workflow Triggered by API                                                                         |
| bcc          | *Optional* List of email ids. It is not a part of email design. To be sent with Events data or from Workflow Triggered by API                                                                         |
| Attachment   | *Optional* Not a part of email design. To be sent as a parameters when [Workflow is triggered from Backend](/docs/trigger-workflow#triggering-workflow-via-api).                                      |
| Email Markup | *Optional* Schema.org markup which allows to add actions in the email itself. Events, tickets, delivery, one click actions, highlights can be sent in email. Use **`handlebarsjs`** to add variables. |

## Display email blocks based on condition

There can be a case where you would want to show or hide some content in the template based on a condition.

To achieve this, you can add a display condition on a block and only show the content of that block to the users who satisfy the given condition. One such example could be to show branding watermarks in email templates to free users and not show them to paid users.

Here's how you can add display condition to an email block:

<Steps>
  <Step title="Add a block and add the relevant content on which you would want to apply the condition." stepNumber="1">
    Display condition can only be applied at a content block level. So, please ensure that you create a separate block for the content that you want to add display condition on

    ![](/images/docs/7d4a897-image.png)
  </Step>

  <Step title="Select the block and click on the 'Display Conditions' checkbox from quick content settings or the right-hand side content settings" stepNumber="2">
    ![](/images/docs/dcc458e-display_email.png)
  </Step>

  <Step title="Add the condition in the editor and click on 'Create new condition'" stepNumber="3">
    * Add a relevant name and description to the condition.

    * You can add condition in this format `(condition <key> "==" <value>)`. You can use any of the [supported conditional operators](/docs/email-template#supported-conditional-operators) in the conditional statement

    ![](/images/docs/baa3119-Group_20.png)

    Once the display condition is created, you can use the same display condition across multiple content blocks.
  </Step>
</Steps>

### Supported conditional operators

| Operator | Returns truthy when                             | Sample Statement       |
| -------- | ----------------------------------------------- | ---------------------- |
| `==`    | LHS equals RHS                                  | 1 `==` "1"             |
| `===`    | LHS value as well as data type matches with RHS | 1 `===` 1              |
| `>`      | LHS is greater than RHS                         | 2 `>` 1                |
| `\<`     | LHS is less than RHS                            | 1 `<` 2               |
| `>=`     | LHS is greater than equals to RHS               | 2 `>=` 2 or 3 `>=` 2   |
| `\<=`    | LHS is less than equals to RHS                  | 2 `<=` 2 or 1 `<=` 2 |
| `!=`     | LHS is not equals RHS                           | 3 `!=` 1               |
| `!==`    | LHS value or data type does not equal RHS       | 1 `!==` "1"            |

 **`OR` condition**

For cases where your condition looks like `users belonging to New York or Chicago`, you can add `or `operator in your display condition. The block will be displayed if one of the conditions is true. Conditional statement for above example will look like this:

**(or (condition city "==" "New York") (condition city "==" "Chicago"))**

You can add as many conditions in the `or` statement as you want.

**`AND` condition**

For cases where your condition looks like `users with monthly billing >= 100$ and yearly billing >= 1000$`, you can add `and` operator in your display condition. The block will be displayed if all the conditions in `and` statement are true. Conditional statement for above example will look like this:

**(and (condition monthly\_bill ">=" 100) (condition annual\_bill ">=" 1000))**

You can add as many conditions in the `and` statement as you want.

## Email Preview

You will be able to see the sample values in the Preview section, as well as in the Live version when you publish a draft.

If you cannot see your variable being rendered with the sample value, check one of the following:

1. Make sure you have entered the variable name and the sample value in the**Variables**button.

2. Make sure you have entered the correct variable name in the template, as per the`handlebarsjs`guideline.

<Warning>
  At the time of sending communication, if there is a variable present in the template whose value is not rendered due to mismatch or missing, SuprSend will simply discard the template and not send that particular notification to your user.





  Please note that the rest of the templates will be sent.&#x20;



  e.g. If there is an error in rendering Android Push template, but email template is successfully rendered, Android Push notification will not be triggered, but email notification will be triggered by SuprSend.
</Warning>
